## 0. Read this first

### 0.1 This is a bigger proposal change than adding a model

Dropping the LLM contradicts the approved proposal in four places:

| Proposal section | What it currently says |
|---|---|
| §1.5 Scope | *"The advisor will be implemented by integrating a third-party Large Language Model through an Application Programming Interface"* |
| §2.7.1 | A full literature subsection on Large Language Models |
| §3.6.6 | *"personalised responses generated by the Claude language model"* |
| §1.6 Limitations | Limitation 3 is entirely about third-party LLM dependency |


The pivot is defensible: *the proposal's own Limitation 3 identified third-party LLM dependency as a project risk — availability, pricing, policy, output variability. Building the intelligence in-house removes that risk entirely and makes every recommendation traceable to a rule and a number.*

### 0.2 You cannot train a conversational model in 48 hours

| Layer | Technique | Yours? |
|---|---|---|
| Transaction categorisation | Multinomial Naive Bayes (supervised) | ✅ trained by you |
| Personalised findings | Rule engine over your own aggregations | ✅ written by you |
| General finance questions | TF-IDF retrieval over a curated knowledge base | ✅ built by you |
| Response wording | Templates, ranked by severity | ✅ written by you |

The advisor becomes **grounded and explainable**. Every sentence traces to a rule and a number. What you lose: it cannot answer a question nobody anticipated. Say so in the limitations.

### 0.3 One file stands between you and this

The entire swap is replacing `generateReply()` inside `server/src/modules/advisor/advisor.client.ts`. The controller, routes, repository, context builder, conversation persistence and the whole `Advisor.tsx` chat UI stay exactly as they are.

### 0.4 `tasks/todo.md` is stale and understates you

It marks the frontend unwired across Phases 2–8. It isn't — all eleven hooks exist in `client/src/api/hooks/`. Fix the tracker; an examiner will mark you against it.

### 1.1 Schema facts that matter

```sql
-- 002: categories are rows, user-scoped, UUID ids
categories(id uuid, user_id uuid NULL, name text, type text, is_default bool)

-- 006: nine seeded expense defaults
Food · Rent · Transport · Academic · Airtime & Data
Entertainment · Health · Personal Care · Other

-- 003: transactions
transactions(id, user_id, wallet_id, category_id uuid NULL,
             type, amount numeric, description text,
             transaction_date DATE,        -- date only, no clock time
             created_at timestamptz, deleted_at timestamptz)
```

1. The model predicts a **category name**, resolved to that user's `category_id`. It never emits a UUID.

3. `category_id` is already nullable, so "uncategorised" exists as a state.

## 4. Prompt specs

### Prompt 1 — Strip the LLM dependency ✅

Keep `generateReply(history, financialContext): Promise<string>` signature; placeholder body. Export `ADVISOR_PERSONA` as tone guide. Delete `getClient()`, the SDK import, `DEEPSEEK_*` env entries, `@anthropic-ai/sdk` dependency, `ANTHROPIC_*` rows in `.env.example` and README. Remove the "not configured" error path. Do not touch service/controller/routes/repository/context or frontend.

### Prompt 2 — Scaffold the ML workspace

`ml/` at repo root, offline Python producing a JSON artefact for the TS server:
`README.md`, `requirements.txt` (pandas, scikit-learn, joblib — exact pins), `lexicon.json` (nine keys, empty arrays), `generate.py`, `train.py`, `export.py`, `data/.gitignore` (ignore `raw_*.csv`, `*.pdf`), `out/`. Use the exact nine names from migration 006.

### Prompt 3 — Build the lexicon *(by hand — do not delegate)*

40–60 lowercase keywords per category — merchants, abbreviations, M-Pesa description words. Two people, 90 minutes, split categories, then swap and review.

### Prompt 4 — Generate the bootstrap training set

`ml/generate.py`: lexicon → `ml/data/train.csv` (description, amount, category). ~12 rows per keyword from M-Pesa patterns (`"{kw}"`, `"{kw} ltd"`, `"pay bill to {kw}"`, `"buy goods {kw}"`, `"{kw} branch {place}"`, `"merchant payment to {kw}"`, `"customer transfer to {kw}"`, …), places from Nairobi neighbourhoods, per-category amount ranges. 2500–4000 rows, roughly balanced, `random.seed(42)`, print per-category counts.

### Prompt 5 — Import and anonymise real statements

`ml/extract.py`: password-protected M-Pesa PDFs in `ml/data/raw/` via pdfplumber → `ml/data/to_label.csv`. Anonymise phones → `[PHONE]`, receipt refs → `[REF]`, 7+ digit runs → `[NUM]`; drop balance column. Print row count + 10 samples. Then label ~250 rows by hand into `ml/data/test_real.csv`; both label the same 60-row overlap for inter-labeller agreement.

### Prompt 6 — Train and evaluate

`ml/train.py`: train on bootstrap, test on real hold-out only. Lowercase, strip digits/punctuation, amount-bucket token (`amt_xs` <100, `amt_s` <500, `amt_m` <2000, `amt_l` <10000, `amt_xl`). No date features. Compare Dummy baseline, CountVectorizer(1,2)+MultinomialNB (ship), TF-IDF+LogReg (comparison). 5-fold CV macro-F1 on train; accuracy, macro-F1, classification report on real test. Grid-search NB alpha over [0.01, 0.05, 0.1, 0.5, 1.0]. Write `metrics.json`, `confusion_matrix.csv`, `categoriser.pkl`. Note any LogReg gap honestly.

### Prompt 7 — Export the model to JSON

`ml/export.py` → `server/src/modules/categoriser/model.json`: version, trained_at, classes, class_log_prior, vocabulary, feature_log_prob, ngram_range, amount_buckets. Prune low-discrimination vocab if over 2 MB.

### Prompt 8 — TypeScript inference

`server/src/modules/categoriser/` following existing module conventions. `text.ts` (tokenise with unigrams+bigrams, termFrequency, cosineSimilarity — written once). `categoriser.service.ts`: NB inference against `model.json`, softmax, `{ category, confidence, alternatives }`. `POST /api/categoriser/suggest` with requireAuth + Zod; `autoAssign = confidence >= 0.60`. Tests: clear Food, clear Transport, empty description, unknown merchant → low confidence.

### Prompt 9 — Resolve name → `category_id`

User's own expense category by lower(name), then seeded default, then null. Reuse categories repository. Return `{ categoryId, categoryName, confidence, autoAssign }`.

### Prompt 10 — Migration 009 and correction capture

```sql
alter table transactions
  add column if not exists predicted_category_id uuid references categories(id),
  add column if not exists prediction_confidence numeric(4,3),
  add column if not exists user_corrected boolean not null default false;

create index if not exists transactions_corrected_idx
  on transactions(user_corrected) where user_corrected = true;
```

Persist prediction on create; set `user_corrected` when final category differs. No automatic retraining.

### Prompt 11 — Suggestion UI

`use-categoriser.ts` hook; debounce description 400 ms, call at 3+ chars with amount present. ≥0.60: preselect + "suggested — change if wrong". <0.60: top-3 chips. Failure: render nothing. Pass prediction on submit. Use existing UI primitives only.

### Prompt 12 — The insight engine

`server/src/modules/advisor/insights/` — `Finding { id, severity, category?, title, detail, suggestion?, score }`. Rules R1 share spike, R2 dominance >40%, R3 negative net, R4 savings <10%, R5 goal off pace, R6 budget breach, R7 uncategorised >30%, R8 positive streak, R9 no data (<5 txns). Baseline is the user's own history. Reuse dashboard/goals/budgets — no new aggregation SQL. Unit test each rule both ways.

### Prompt 13 — Knowledge base and retrieval

`advisor/kb/knowledge-base.json` (40–60 entries, Kenyan student context, KES). `retrieval.ts` uses `categoriser/text.ts`; cosine similarity, threshold 0.25 → null. Tests: on-topic hit, off-topic null.

### Prompt 14 — The new `generateReply`

Route last user message: data question → snapshot numbers; advice request → top 2–3 findings via templates; general → KB, else top finding, else capability statement. `advisor/templates.ts`, phrasing pools per severity. Real numbers only, one concrete action, disclaimer on loans/debt/investment. No external calls. Router tests per branch.

### Prompt 15 — Refresh the project tracker

Audit `tasks/todo.md` against code; tick only what is verified. Rewrite Phase 8; add Phase 11 (Categorisation Model) and Phase 12 (Self-Hosted Advisor Engine); flag budgets/gamification as extensions.

### Prompt 16 — Update the architecture docs

`docs/architecture/system-architecture.md` and `class-diagram.md`: no outbound calls; categoriser; insight engine; KB sharing text utilities; router; feedback path; why no separate Python service. Mermaid, matching existing style.

### 5.2 For the write-up

`ml/out/metrics.json` (baseline vs NB vs LogReg), confusion matrix heatmap, per-class P/R/F1 on the real test set, inter-labeller agreement, top keywords per category, rule-coverage table.

### 5.3 The paragraph you must not skip

> The training set was generated from a hand-built lexicon of Kenyan merchant names and transaction-description patterns rather than from labelled user data, since the system had no users during development. The model was evaluated on a held-out set of **real, manually labelled M-Pesa transactions** that took no part in training or tuning. Reported accuracy therefore measures whether the lexicon bootstrap generalises to genuine transaction descriptions. A production deployment would retrain on accumulated user corrections.

### 5.4 Limitations to state

- The advisor cannot answer questions outside its rule set and knowledge base.
- Income transactions are not classified.
- Insights are weak in a user's first month (baseline is own history).
- The lexicon is Nairobi-specific.
